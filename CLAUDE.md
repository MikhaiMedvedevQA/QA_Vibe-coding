## Агенты и скилы

В проекте используются субагенты с разделёнными зонами ответственности:

- **router** — выбирает, какой агент отвечает за запрос. Описание: `.claude/agents/router.md`.
- **qa-assistant** — ассистент QA-инженера: чек-листы, тест-кейсы, баги, оценки по спецификациям ЭФ. Описание: `.claude/agents/qa-assistant.md`.

Реестр агентов: `.claude/agents/*.md` с YAML-шапкой (`name`, `description`, `model`, `tools`).

Модели: все агенты — `claude-sonnet-4-6`.

Скилы агентов лежат в `.claude/skills/<имя-скилла>/SKILL.md`:

## Excel-спецификации полей ЭФ и JSON-датасет

Отдельных агентов-валидаторов для Excel-спецификаций нет: извлечение структуры полей делает анонимизатор (`tools/anonymize`). При обработке `.xlsx` рядом с `<stem>_anon.md` кладётся канонический JSON-датасет `<stem>_anon.json` (модуль `tools/anonymize/spec_extractor.py`): детекция столбцов по маркерам, параметры полей с блоками, статусы `required`/`default`/`hidden`, source-координаты, анонимизация значений через mapper. Сводный `anonimized/index.json` содержит `spec_dataset` со ссылкой и summary.

Скиллы (`validation-positive/-negative/-full`, `required-fields`, `default-values-checklist`, `field-availability`, `qa-full-coverage`, `qa-full-coverage-v2`) принимают **JSON-датасет анонимизатора** как основной вход для Excel-спецификаций + текст для небольших ТЗ. Не парсят Excel напрямую. Архитектура и обоснование — в памяти `skills-excel-input-plan` (Вариант B: слой данных стабилен, слой генерации меняется).

# Как работаем

- **Подход:** сначала план, потом действие. Агент показывает шаги и ждёт подтверждения, прежде чем что-то менять или создавать. Если задача однозначна и мелкая (правка одной строки, одиночный запрос) — можно действовать сразу, но в сомнительных случаях всегда план первым.
- **Уточнения:** задавать только по делу и только когда без ответа нельзя продолжить. Не переспрашивать то, что уже сказано.
- **Проверка результата:** в конце работы агент возвращает:
  1. Список изменённых/созданных файлов с путями.
  2. Короткий итог: что сделано и что осталось / не сделано.
  3. Ссылки на источники или обоснования, если в ходе работы был выбор между вариантами.

#### Правила нейминга

Формула имени файла: `[дата — опционально] — [тема] — [тип].md`
- Дата в ISO `YYYY-MM-DD`, ставится опционально (для датированных артефактов: баги, прогоны, сессии).
- Разделитель — ` — ` (длинное тире с пробелами), как в уже заведённых баг-репортах.
- `тема` — краткое человекочитаемое описание на русском. **Внутри темы НЕ использовать ` — `** (это разделитель формулы — парсинг по частям сломается) и **запрещённые в Windows символы** (`< > : " / \ | ? *`); для уточнения внутри темы использовать скобки. Пример: `PRODUCT_0011 (обязательность полей)`, не `PRODUCT_0011 — обязательность полей` и не `PRODUCT_0011: обязательность полей`.
- `тип` — суффикс по назначению файла, привязан к папке (см. ниже).

Типы по папкам:
- `templates/` — `template` (шаблоны без даты): `bug-report-template.md`, `test-case-template.md`, `run-report-template.md`.
- `work/test-cases/` — `tst-cs` (тест-кейсы) и `chk-lst` (чек-листы): `2026-04-21 — Оформление полиса — tst-cs.md`, `2026-07-26 — PRODUCT_0011 (обязательность полей) — chk-lst.md`.
- `work/bug-reports/` — `bug`: `2025-03-19 — Дублирование пути в навигации — bug.md`.
- `work/api/` — `api` (примеры/заметки): `2026-04-21 — Расчёт премии — api.md`. Коллекции Postman — `…postman_collection.json`.
- `work/exploratory/` — `exploratory`: `2026-04-21 — Поиск в каталоге — exploratory.md`.
- `work/environments/` — `env` (без даты): `stage.env.md`, `prod.env.md`.
- `references/` — `ref` (без даты, если документ не датирован): `insurance-rules.ref.md`.
- `learn/python|selenium|playwright/` — `notes` / `exercise` / `project`: `2026-04-21 — playwright-locators — notes.md`.

Примеры:
- `2025-03-19 — Дублирование пути в навигации по сайту — bug.md`
- `2026-04-21 — Оформление полиса — tst-cs.md`
- `2026-07-26 — PRODUCT_0011 (обязательность полей) — chk-lst.md`
