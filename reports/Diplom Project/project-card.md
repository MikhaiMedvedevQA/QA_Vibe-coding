# **QA-Ассистент: Анонимизированный генератор чек-листов**

## Проблема

В разработке ПО B2B для страхового бизнеса для описания полей электронных форм (ЭФ) используются Excel-таблицы с конфиденциальными данными — ФИО, наименования банков, страховых компаний, продуктов, партнёрских программ. Передавать такие спецификации во внешние AI-инструменты напрямую нельзя (утечка ПД и коммерческой тайны), а вручную обезличивать и писать чек-листы по каждой доработке — долго и чревато ошибками. Спецификации меняются редко, а промпты/правила тестирования — часто, поэтому каждый раз перерабатывать Excel неэффективно.

## Пользователь

QA-инженер B2B/B2C-продуктов страховой компании. Опосредованно — команда тестирования и аналитики, которые получают готовые чек-листы для.

## Основная функция

Сервис выполняет конвейер из двух разделённых слоёв.

**Вход:** `.xlsx`/`.docx`/`.pdf`/`.txt` спецификация ЭФ (исходное ТЗ с конфиденциальными данными).

### Слой данных (стабильный) — анонимизатор `tools/anonymize/`

- Заменяет ПД и сущности на структурированные псевдонимы (`PERSON_0001`, `BANK_0001`, `INS_0001`, `PRODUCT_0011`) с устойчивым маппингом между запусками.
- Извлекает структуру полей ЭФ в канонический JSON-датасет: параметры полей, блоки, статусы `required`/`default`/`hidden`, source-координаты, анонимизированные значения.
- Флагует подозрительные совпадения, не ставшие псевдонимом, в review-файл для ручного разбора.
- Выход: `<stem>_anon.md` (обезличенный текст) + `<stem>_anon.json` (датасет полей) + `<stem>_anon_review.json` (кандидаты на ревью) + сводный `anonimized/index.json`.

### Слой генерации (меняется часто) — скиллы `.claude/skills/`

- Принимают на вход JSON-датасет анонимизатора (не Excel напрямую) + опционально текстовое ТЗ.
- Генерируют атомарные чек-листы по конкретным аспектам: обязательность полей, значения по умолчанию, условная доступность/видимость, позитивная/негативная/полная валидация, полное покрытие.
- Маршрутизация запроса к нужному скиллу — через агента `router`.

**Инструменты:** Python (анонимизатор), PyMuPDF, python-docx, openpyxl, pandoc; Claude Code (агенты и скиллы); словари сущностей `dictionaries/*.txt`.

## Формат результата

Markdown-чек-листы для ручного прогона (один чек-лист на одну ЭФ, табличная форма: шаг / значение / ожидаемый результат), разложенные по аспектам проверки. Плюс обезличенный Markdown-файл спецификации и JSON-датасет полей для повторного использования.

## Минимальный функционал (MVP)

Реализовано в первой версии:

- **Анонимизатор:** извлечение текста из xlsx/docx/pdf/txt, замена сущностей по словарям, устойчивый маппинг, извлечение структуры полей ЭФ в JSON, review-механизм с flag-файлом, омоглиф-фикс латиницы→кириллицы, GUI-панель ревью.
- **Скиллы:** генерация чек-листов по обязательности, дефолтам, доступности полей, валидации, полному покрытию; эссе-самопрезентации; обучающие и кодинговые скиллы.
- **Агенты:** `router` + `qa-assistant` + `python-coder` + `learn-assistant` с разделением зон ответственности.
- **Тесты:** pytest-кейсы на детекторы и review-механизм.

Планируется добавить:

- Генерация автотестов на Python (Selenium + pytest + Allure) из того же JSON-датасета — без переразбора Excel.
- Сравнение версий спецификаций как diff двух JSON.
- MCP-подключения (Jira, Яндекс.Диск, Telegram-бот).

## Технологии

- **Язык:** Python (слой данных), промпты/скиллы на естественном языке (Claude Code).
- **Библиотеки:** PyMuPDF, python-docx, openpyxl, pandoc; pytest для тестов.
- **Платформа:** Claude Code (субагенты, скиллы, маршрутизация).
- **Форматы:** вход — `.xlsx`/`.docx`/`.pdf`/`.txt`; промежуточный — `.json` (датасет полей, review-файл, сводный индекс); выход — `.md` (чек-листы, обезличенный текст).
